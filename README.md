# BahonIQ Music Stable Edition

Финальная стабилизация онлайн-воспроизведения и офлайн-сохранения.

## Команда для Antigravity

> Установи архив в корень актуального проекта с сохранением структуры каталогов. Замени только файлы из архива. Не изменяй `.env`, Telegram-сессию, Telegram API ID/HASH, username канала и существующую базу `data/music_catalog.db`. Запусти `node --check web_app/static/music/music.js` и `python -m unittest discover tests`. После успешной проверки сделай commit, push в main и дождись успешного деплоя Render.

## Что принципиально изменено

- Удалено прямое нестабильное проксирование каждого HTTP Range из браузера в Telegram.
- Telegram-документ один раз скачивается в проверенный временный серверный кэш Render через файл `.part`.
- После проверки точного размера `.part` атомарно превращается в готовый `.bin`.
- `/stream` и `/download` читают один локальный серверный файл и всегда отдают точный `Content-Length`.
- Параллельные запросы одного трека объединяются одним lock: повторной Telegram-загрузки нет.
- Серверный кэш ограничен 256 МБ и автоматически удаляет старые треки; лимит можно изменить переменной `MUSIC_SERVER_CACHE_MB`.
- После перезапуска Render кэш автоматически восстанавливается при первом обращении к треку.
- Удалён жёстко заданный старый ID канала; используются `TELEGRAM_CHANNEL_ID`, затем `TELEGRAM_CHANNEL_USERNAME`, затем резервный поиск.
- Исправлена строгая проверка локальных OPFS/IndexedDB-файлов.
- OPFS снова использует временный `.part` и точную проверку размера.
- Добавлена миграция офлайн-треков из старой базы браузера `BahonIQ_Music_DB` в актуальную `bahoniq_music_store`.
- Service Worker обновлён до `v17-stable`.

## Ожидаемое поведение

При первом запуске ещё не кэшированного трека может быть короткая пауза в несколько секунд, пока Render получает полный файл из Telegram. Следующие запуски, перемотка и офлайн-скачивание этого трека работают из серверного кэша стабильно.
